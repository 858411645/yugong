# 复刻愚公移山游戏（增强版）

## 目标

复刻经典放置/点击类游戏《愚公移山》，并融入 4 大独特玩法系统，打造超越原版的深度放置体验。

## 原版核心机制（已研究确认）

| 系统 | 内容 |
|------|------|
| **核心循环** | 手动点击挖山 → 积累资源 → 招募子孙 → 自动化挖掘 → 升级效率 → 推平山脉 |
| **子孙系统** | 消耗资源招募劳动力，升级单个子孙效率，解锁特殊角色（如智叟） |
| **自动化** | 子孙自动挖掘，离线收益累计，中后期完全自动化 |
| **转生系统** | 推平一座山后转生，获得永久加成，以更强能力挑战下一座山 |
| **升级路线** | 前期手动+快速招募 → 中期平衡工具与子孙 → 后期转生分配永久加成 |

## 独特玩法（4大系统）

### 1. Roguelike 事件系统
- 挖山过程中随机触发事件（塌方/宝藏/神灵显灵/山贼袭扰等）
- 每次事件出现 2-3 个选项，不同选择带来不同增益/减益
- 事件结果影响资源、子孙效率、村庄状态

### 2. 多路线科技树
- 不再线性升级，分 3 条分支：
  - **人力线**：提升子孙数量与效率
  - **神力线**：解锁神话加成（夸娥氏、山神等）
  - **机械线**：解锁工程器械（杠杆、滑轮、炸药等）
- 不同路线带来不同加成组合，支持混合加点

### 3. 村庄经营
- 不仅挖山，还要管理村庄：
  - **人口**：需要住房和食物支持
  - **食物**：农田产出，供养子孙
  - **士气**：影响工作效率
- 挖山与村庄发展互相制约：过度挖山消耗人口，村庄发展提供更强劳动力

### 4. 转生/轮回系统
- 移完一座山后转生，获得「功德」点数
- 功德可投入不同方向获得永久加成
- 每次转生解锁新的科技节点和事件

## 里程碑交付策略

| 里程碑 | 内容 | 预计产出 |
|--------|------|----------|
| **M1** | 核心挖山 + 子孙自动化 + 基础 UI | 可玩的基础放置游戏 |
| **M2** | 科技树 + 村庄经营 | 深度策略层 |
| **M3** | 转生 + Roguelike 事件 | 完整游戏循环 |

本次任务聚焦 **M1**。

## M1 山脉设计

- **单山模式**：M1 只有一座山（王屋山），血量足够大以完整体验核心循环
- M3 引入转生后再加入多山系统（太行山、昆仑山等）

## M1 需求

- 可点击挖山的核心交互（点击区域 + 进度条 + 数值反馈）
- 资源系统：泥土/石块（基础资源）
- 子孙招募：消耗资源增加自动挖掘产量
- 子孙升级：提升单个子孙效率
- 离线收益：离开游戏后自动累积（基于当前子孙效率）
- 数据持久化：localStorage 保存/读取
- 基础 UI：资源栏、点击区、升级面板、子孙面板

## M1 验收标准

- [ ] 用户可点击进行挖山操作，有视觉/数值反馈
- [ ] 存在子孙招募与升级系统
- [ ] 子孙可自动产生资源（自动化）
- [ ] 游戏进度可保存/恢复（localStorage）
- [ ] 可在浏览器中流畅运行（无框架，纯 HTML/CSS/JS）
- [ ] 响应式布局，支持移动端触控

## 技术方案

- **平台**：纯前端 Web，单文件架构
- **技术栈**：HTML + CSS + Vanilla JS（无框架）
- **数据持久化**：localStorage
- **文件结构**：
  - `index.html` — 主入口（游戏容器）
  - `src/game/style.css` — 样式（已有基础布局）
  - `src/game/main.js` — 游戏核心逻辑（状态管理 + 渲染 + 事件）
  - `src/game/data.js` — 数据配置（升级表、价格曲线等）

## 排除范围（M1）

- 科技树系统（M2）
- 村庄经营（M2）
- 转生系统（M3）
- Roguelike 事件（M3）
- 音效
- 多人联机

## 决策记录（ADR-lite）

**Context**：4个独特系统全部实现开发量过大  
**Decision**：分3个里程碑交付，M1 聚焦核心循环  
**Consequences**：M1 代码需预留扩展接口（事件钩子、科技树节点挂载点、村庄状态槽位）
