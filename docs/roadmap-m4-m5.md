# 愚公移山 M4/M5 后续规划

## 当前阶段

当前游戏已经完成到 M3：

- M1：核心挖山、资源、招工、升级、离线收益、localStorage 存档。
- M2：科技树、村庄经营、人口、住房、食物、士气。
- M3：多山推进、推平后转生、功德永久加成、Roguelike 奇遇事件。

现阶段已经具备完整闭环，但内容深度、长期目标、平衡调试、发布体验还不足。M4/M5 的重点应从“系统能跑”转向“可长期游玩、可调优、可发布”。

## M4：内容扩展与长期目标层

### 目标

把当前可运行闭环扩展为更完整的中长期放置游戏体验，让玩家在多轮转生中有明确目标、阶段解锁和差异化策略。

### 主要任务

1. 山脉图鉴
   - 为每座山增加描述、特殊规则和首通奖励。
   - 不同山影响资源倾向，例如太行山石块更多，昆仑余脉事件更频繁。
   - UI 增加当前山特性展示。

2. 成就系统
   - 覆盖点击次数、总挖掘量、子孙数量、科技数量、转生次数、事件选择。
   - 成就给予小型永久奖励或一次性资源奖励。
   - 成就状态进入存档。

3. 任务目标系统
   - 增加短期目标，例如“招募 10 名子孙”“研究 3 项科技”“建造 5 块农田”。
   - 目标完成后给资源或士气奖励。
   - 目标用于引导玩家理解 M1-M3 系统。

4. 奇遇事件扩充
   - 从当前 3 个事件扩展到 12 个左右。
   - 增加事件标签：资源、村庄、神力、器械、风险。
   - 部分事件根据科技、功德路线或当前山解锁。

5. 平衡曲线第一轮
   - 调整山体血量、科技成本、招工成本、食物消耗、功德收益。
   - 目标是第一轮 5-10 分钟可完成，第二轮明显加速但仍有选择空间。

### 验收标准

- 至少 5 座山，每座有不同特性。
- 至少 12 个奇遇事件。
- 至少 10 个成就。
- 至少 8 个阶段目标。
- 成就、目标、山脉进度都可保存和恢复。
- 完整 smoke test 覆盖：完成目标、解锁成就、触发山特性、转生后保留长期奖励。

## M5：发布质量与体验打磨

### 目标

把游戏从“功能完整”提升到“可以稳定试玩和迭代”的状态，重点是可用性、可维护性、可验证性和发布准备。

### 主要任务

1. 新手引导
   - 首次进入给出轻量教程。
   - 引导点击、招工、科技、村庄、奇遇、转生。
   - 不使用长说明文本，尽量通过任务目标和高亮提示完成。

2. 存档管理
   - 增加导出/导入存档。
   - 增加存档版本迁移入口。
   - 增加重置二次确认和当前存档摘要。

3. 设置与可访问性
   - 增加数字显示模式、减少动画、字体大小选项。
   - 优化移动端按钮密度和滚动体验。
   - 检查颜色对比和小屏文字溢出。

4. 自动化测试脚本
   - 增加可重复运行的 Node smoke test。
   - 覆盖 M1-M4 关键行为：资源、招工、科技、村庄、事件、转生、成就、存档迁移。
   - 将当前临时命令沉淀为脚本。

5. 发布入口
   - 增加 README 的运行说明和功能说明。
   - 准备静态站点发布方式。
   - 检查无外部依赖、无控制台错误、浏览器直接打开可玩。

### 验收标准

- 首次游玩 1 分钟内能理解核心操作。
- 支持导出/导入存档。
- 有固定 smoke test 命令，并能通过。
- 桌面和移动端首屏布局无明显重叠。
- README 能说明玩法、运行方式、里程碑状态。
- Playwright 截图检查通过。

## 推荐执行顺序

1. M4-1：山脉图鉴与山特性。
2. M4-2：成就系统。
3. M4-3：任务目标系统。
4. M4-4：奇遇事件扩充。
5. M4-5：第一轮平衡曲线。
6. M5-1：新手引导。
7. M5-2：存档导出/导入与迁移。
8. M5-3：自动化 smoke test。
9. M5-4：移动端与可访问性打磨。
10. M5-5：README 与发布准备。

## 暂不纳入 M4/M5

- 多人联机。
- 后端服务。
- 付费、广告、账号系统。
- 大规模美术资源生产。
- 引入前端框架或构建系统。
